# 用户态网络栈详解

## 🌐 什么是 SLIRP?

**SLIRP** (Serial Line IP) 是一个用户态网络栈实现,允许虚拟机完全独立地进行网络通信,而不需要真实的网络接口或内核网络驱动。

### SLIRP vs 传统网络栈

| 方面 | SLIRP | 传统网络 |
|------|--------|---------|
| **运行位置** | 用户态进程 | 内核态 |
| **网卡需求** | 无 (虚拟) | 需要真实网卡 |
| **MAC 地址** | 虚拟 | 真实 |
| **性能** | 中等 | 高性能 |
| **隔离性** | 完全隔离 | 部分隔离 |
| **配置复杂度** | 简单 | 复杂 |
| **内存占用** | 低 | 中等 |

## 📡 数据包处理流程

### 场景: 虚拟机浏览器访问 google.com

#### 步骤 1: DNS 查询

```
VM 应用层
  │
  └─► socket call: getaddrinfo("google.com")
      │
      ▼
      Linux Network Stack (VM内)
      │
      ├─► 构造 DNS 查询包
      │   源: 10.0.2.15:12345
      │   目的: 10.0.2.3:53 (虚拟 DNS)
      │   查询: google.com A 记录
      │
      └─► VIRTIO 虚拟网卡
          │
          ▼
      SLIRP 引擎 (QEMU 进程)
      │
      ├─► 1. 包接收
      │     检测目的 IP: 10.0.2.3 = 本地 DNS
      │
      ├─► 2. DNS 处理
      │     检查本地缓存
      │     如缓存未命中:
      │       - 向主机 DNS 递归查询 (8.8.8.8:53)
      │       - 缓存结果
      │
      ├─► 3. DNS 响应
      │     构造响应包
      │     源: 10.0.2.3:53 → 10.0.2.15:12345
      │     答案: google.com = 142.251.42.46
      │
      └─► 发送回虚拟机
          │
          ▼
      VM 应用层
      │
      └─► DNS 缓存: google.com = 142.251.42.46 ✓
```

#### 步骤 2: TCP 连接建立

```
VM 应用层 (Chromium)
  │
  └─► socket call: connect("142.251.42.46", 80)
      │
      ▼
      Linux Network Stack (VM内)
      │
      ├─► 构造 SYN 包
      │   源: 10.0.2.15:54321 (虚拟端口)
      │   目的: 142.251.42.46:80
      │   TCP 标志: SYN
      │
      └─► VIRTIO 虚拟网卡
          │
          ▼
      SLIRP 引擎 (QEMU 进程)
      │
      ├─► 1. 包接收和解析
      │     协议: TCP
      │     源 IP: 10.0.2.15 (虚拟)
      │     目的 IP: 142.251.42.46 (目标)
      │     源端口: 54321 (虚拟)
      │     目的端口: 80
      │
      ├─► 2. NAT 转换 (出站)
      │     虚拟端口 54321 → 映射端口 55001
      │     记录连接:
      │       (10.0.2.15:54321) → (142.251.42.46:80)
      │       映射为:
      │       (host_ip:55001) → (142.251.42.46:80)
      │
      ├─► 3. 发出真实连接
      │     源: host_ip:55001
      │     目的: 142.251.42.46:80
      │     使用主机真实网卡
      │
      └─► Google 服务器 (互联网)
          │
          ├─► 收到连接
          ├─► 发送 SYN-ACK
          │
          ▼
      SLIRP 引擎 (收到响应)
      │
      ├─► 1. 包接收
      │     源: 142.251.42.46:80
      │     目的: host_ip:55001
      │     TCP 标志: SYN-ACK
      │
      ├─► 2. 反向 NAT 转换
      │     查找连接表
      │     55001 → 54321
      │     (host_ip:55001) → (10.0.2.15:54321)
      │
      ├─► 3. 转换响应包
      │     源: 142.251.42.46:80
      │     目的: 10.0.2.15:54321
      │
      └─► VIRTIO 虚拟网卡
          │
          ▼
      VM 的 Linux Network Stack
      │
      ├─► TCP 层处理
      │     识别连接: 54321
      │     发送 ACK
      │
      └─► VM 应用层
          │
          └─► 连接已建立 ✓
```

#### 步骤 3: 数据传输

```
VM 应用层 (Chromium)
  │
  └─► send(socket, "GET / HTTP/1.1\r\n...")
      │
      ▼ 数据经过完全相同的 NAT 流程
      
      SLIRP 处理:
      1. 接收虚拟 TCP 包 (10.0.2.15:54321 → 142.251.42.46:80)
      2. NAT 转换 (host_ip:55001 → 142.251.42.46:80)
      3. 发送真实请求
      
      ▼
      
      Google 服务器处理请求并响应
      
      ▼
      
      SLIRP 处理:
      1. 接收响应 (142.251.42.46:80 → host_ip:55001)
      2. 反向 NAT (142.251.42.46:80 → 10.0.2.15:54321)
      3. 发送回虚拟机
      
      ▼
      
      VM 应用层
      │
      └─► recv(socket, buffer) = HTML 数据 ✓
```

## 🔄 NAT 连接表管理

SLIRP 维护一个连接表来跟踪所有虚拟连接:

```
连接表示例:

┌─────────────────────────────────────────────────────────────┐
│  连接 ID │  虚拟端            │  真实端口  │  目标             │
├─────────────────────────────────────────────────────────────┤
│    1     │  10.0.2.15:54321  │  55001    │  google.com:80   │
│    2     │  10.0.2.15:54322  │  55002    │  facebook.com:443│
│    3     │  10.0.2.15:53     │  DNS      │  8.8.8.8:53      │
│    4     │  10.0.2.15:54323  │  55003    │  github.com:443  │
└─────────────────────────────────────────────────────────────┘

状态机:

LISTEN
  │
  ├─► 虚拟机: SYN 发送 (54321)
  │
  ▼
SYN_SENT
  │
  ├─► SLIRP: 映射端口 (55001)
  ├─► SLIRP: 向实际服务器发送 SYN
  │
  ▼
SYNS_RCVD
  │
  ├─► 服务器: 返回 SYN-ACK
  ├─► SLIRP: 反向 NAT
  ├─► SLIRP: 发送给虚拟机
  │
  ▼
ESTABLISHED
  │
  ├─► 数据双向流动
  ├─► NAT 转换继续进行
  │
  ▼
FIN_WAIT / TIME_WAIT
  │
  ├─► 关闭连接
  ├─► 清理条目
  │
  ▼
CLOSED
```

## 🛡️ 网络隔离的优势

### 1. 完全隔离

```
传统网络 (问题):
┌──────────────────────────┐
│  虚拟机 1                 │
│  192.168.1.100           │
└──────────────────────────┘
           │
           ├─► 可能访问网络上的其他虚拟机
           ├─► 可能被网络上的主机扫描
           └─► 可能产生 ARP 冲突
           
SLIRP 网络 (隔离):
┌──────────────────────────┐
│  虚拟机                  │
│  10.0.2.15 (虚拟)        │
│  无法被外部网络访问      │
│  无法访问其他虚拟机      │
│  无法产生 ARP 冲突       │
└──────────────────────────┘
```

### 2. 无 MAC 地址泄露

```
传统网络:
└─► 虚拟网卡有真实 MAC 地址
    └─► 可被网络嗅探工具发现
    └─► 可被追踪和识别

SLIRP:
└─► 虚拟网络不生成真实 MAC
    └─► 无法被网络嗅探工具发现
    └─► 无 MAC 地址签名
    └─► 完全隐形
```

### 3. 端口隔离

```
VM 应用尝试监听端口 80:

传统桥接模式:
└─► 可能冲突! 
    └─► 主机也想用 80
    └─► 导致错误

SLIRP:
└─► 虚拟 80 和真实 80 完全隔离
    └─► 无冲突!
    └─► 可以同时监听
```

## ⚙️ SLIRP 配置选项

### 启用网络

```bash
qemu-system-x86_64 \
  -net user,hostname=vm-hostname \
  -net nic,model=virtio
```

### 端口转发

```bash
# 将虚拟机的 8080 暴露到主机的 9080
qemu-system-x86_64 \
  -net user,hostfwd=tcp::9080-:8080 \
  -net nic,model=virtio

# 使用 socat 手工转发
socat TCP-LISTEN:9080,reuseaddr TCP:10.0.2.15:8080

# 结果: 主机访问 localhost:9080 → VM 的 8080
```

### DNS 配置

```bash
# 使用自定义 DNS
qemu-system-x86_64 \
  -net user,dns=8.8.8.8 \
  -net nic,model=virtio

# VM 内部查看
$ cat /etc/resolv.conf
nameserver 10.0.2.3

# SLIRP 自动转发到 8.8.8.8
```

### DHCP 范围

```bash
# 默认: 10.0.2.15 到 10.0.2.255
# 可自定义但需修改 SLIRP 源码
```

## 📊 性能特性

### 吞吐量

```
本地 iperf 测试:

SLIRP:
  TCP 吞吐量: 50-100 Mbps
  延迟: 1-5 ms
  
TAP 网络:
  TCP 吞吐量: 500-1000 Mbps
  延迟: 0.5-2 ms

性能权衡:
  - SLIRP: 简单、隔离强、性能一般
  - TAP: 性能高、配置复杂、隔离弱

对于浏览器应用:
  SLIRP 完全足够 (>10 Mbps 即可)
```

### CPU 开销

```
SLIRP NAT 处理:
  per 包: 1-2 μs
  per 连接: 10-50 μs
  
总体: < 5% CPU 额外开销 (对于轻度网络使用)
```

## 🔍 调试 SLIRP 网络

### 在虚拟机内测试

```bash
# 检查网络配置
$ ip addr show
eth0: inet 10.0.2.15/24

$ ip route show
default via 10.0.2.1

# 测试 DNS
$ nslookup google.com
Server:      10.0.2.3
google.com   A 142.251.42.46

# 测试连接性
$ ping 10.0.2.1        # 网关
$ ping 10.0.2.3        # DNS
$ ping 142.251.42.46   # Google

# 测试 TCP 连接
$ curl http://google.com
(应该返回 HTML)

# 查看网络统计
$ netstat -an
$ ss -ant
```
